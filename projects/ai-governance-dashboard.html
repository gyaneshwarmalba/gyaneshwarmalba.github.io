AI Governance Dashboard

Observability and governance for AI systems

One place to see how AI applications and agents behave in practice: what they were asked, what they answered, what it cost, how long it took, and whether it followed policy.

View on GitHub

The problem

As teams ship more LLM features, it becomes hard to answer basic questions: Which prompts are failing? What is this costing? Did any response break policy? Without a shared view, governance turns into manual spot checks and quality problems are found by users first.

Architecture

  1. Apps and agentsLLM applications emit traces for every request
  2. TelemetryOpenTelemetry and LangSmith capture prompts, responses, latency, and token usage
  3. StoreTelemetry lands in Databricks for history and analysis
  4. Dashboard UIStreamlit views of quality, cost, latency, and policy results
  5. Alerts and policiesPolicy checks flag issues and route them to human review

Key design decisions

  • Open telemetry standards. OpenTelemetry keeps the dashboard independent of any one model provider or framework.
  • Cost and quality side by side. Showing spend next to quality signals makes trade-offs visible when choosing models or prompts.
  • Policies as checks, not documents. Governance rules run automatically against real traffic instead of living only in a policy wiki.
  • Human review hooks. Flagged responses go to a person, and their decisions feed back into evaluation.

Tech stack

  • Python
  • Streamlit
  • OpenTelemetry
  • LangSmith
  • Databricks
