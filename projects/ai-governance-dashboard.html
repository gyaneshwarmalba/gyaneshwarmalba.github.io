AI Governance Dashboard

Enforce, observe, and audit every LLM call

A gateway that every LLM call passes through, handling attribution, budgets, guardrails, pricing, tracing, and audit, plus a dashboard for the people accountable for AI spend and risk.

View on GitHub

The problem

Once several teams use LLMs, the same questions come up: who is spending what, which model is right for each workload, whether sensitive data is reaching the model, and whether you can prove what happened afterwards. Dashboards built from logs answer some of this after the fact, but controls like redaction and budget stops have to happen before the call.

Architecture

  1. AttributionCalls must name a registered team and a model on the approved price list
  2. Budget checkMonth-to-date spend per team; alerts at 80% and 100%, optional hard stop
  3. Input guardrailsRedact emails, phone numbers, SSNs, and Luhn-valid card numbers; block prompt injection and policy-blocked topics
  4. ProviderAWS Bedrock, or a seeded simulator for offline demos
  5. Output guardrails and pricingRedact personal data in responses; cost from a versioned price table
  6. Trace and auditAn OpenTelemetry span per call with GenAI attributes, plus an entry in a SHA-256 hash-chained audit log

Key design decisions

  • A gateway, not log scraping. Enforcement and observability come from the same code path, so dashboard numbers always match the decisions that were made.
  • OpenTelemetry as the contract. Spans follow the GenAI semantic conventions and can be exported over OTLP to any backend. The local SQLite exporter only exists to make the dashboard self-contained.
  • Tamper-evident audit. Editing or deleting any audit row is detected, and the first broken entry reported. Prompts are stored as a hash plus a redacted preview, never in clear.
  • Policy as data. Pricing, budgets, thresholds, and guardrail actions live in one JSON file, and every span records the policy version it was evaluated against.
  • Decision support, not just charts. Model comparisons show cost per 1,000 calls next to latency and errors, and prompt-template views show whether v2 should replace v1.

Run it

git clone https://github.com/gyaneshwarmalba/ai-governance-dashboard.git
cd ai-governance-dashboard
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app.cli simulate        # 30 days of governed traffic
python -m app.cli verify-audit
streamlit run app/dashboard.py
pytest

The simulator sends about 1,500 calls through the real gateway, including PII, injection attempts, blocked topics, provider errors, and a team that runs over budget.

Status

Working demo with 22 automated tests running in CI. The gateway, guardrails, budgets, audit chain, and dashboard run offline. Bedrock and OTLP export are switched on through configuration and have not yet been validated against live accounts. Guardrails are regex and heuristic detectors meant as a first layer; a dedicated DLP or safety classifier can be added behind the same interface.
