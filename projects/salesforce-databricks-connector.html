Salesforce-Databricks Connector

Real-time sync into analytics-ready, governed tables

Captures changes in Salesforce, lands them in Databricks, and refines them into governed tables that analytics and AI features can rely on.

View on GitHub

The problem

Salesforce holds valuable operational data, but analytics and AI work needs that data in a lakehouse: current, clean, and governed. Nightly exports go stale, and ad-hoc pulls create inconsistent copies with no lineage.

Architecture

  1. SalesforceChange Data Capture events, with Bulk or REST APIs for backfills
  2. Ingestion serviceReceives changes and writes them to a landing zone
  3. DatabricksDelta Lake bronze and silver tables apply cleaning, deduplication, and schema checks
  4. Gold tables and featuresGoverned, analytics-ready data for reporting and AI use cases

Key design decisions

  • Change Data Capture over polling. Events keep data fresh without repeatedly querying Salesforce and consuming API limits; bulk APIs are kept for backfills and recovery.
  • Land raw, then refine. Keeping the raw change stream makes reprocessing and auditing possible when business rules change.
  • Governance built in. Tables are designed for Unity Catalog permissions and lineage, so downstream AI use is controlled from the start.
  • Designed for reuse. Gold tables serve both reporting and AI features, avoiding one-off copies for each consumer.

Tech stack

  • Python
  • PySpark
  • Databricks
  • Delta Lake
  • Salesforce CDC
