Salesforce-Databricks Connector

Change Data Capture into Delta Lake, and governed write-back

Applies Salesforce change events to Delta Lake with one idempotent MERGE per object per batch, handling the cases that break naive syncs: partial updates, deletes, gaps, and new fields. Model scores can be written back to Salesforce without creating a feedback loop.

View on GitHub

The problem

Analytics and AI teams need Salesforce data in the lakehouse, and business users need model results back in Salesforce. Nightly full exports are slow and expensive, and simple upsert scripts quietly corrupt data: CDC updates carry only the changed fields, events arrive late or are replayed, and Salesforce sometimes sends gap events instead of data.

Architecture

  1. SourceReplay of CDC events from a file, or a REST poller on SystemModstamp that works in any org
  2. Validate and filterMalformed events go to a dead-letter file; the connector's own write-back events are dropped
  3. Gap recoveryGAP_* events re-fetch the affected records; GAP_OVERFLOW triggers a full resync
  4. CompactFold each batch into one net change per record
  5. MERGEPartial-column updates, deletes and undeletes, schema evolution, and a commit-timestamp guard against stale events
  6. CheckpointAdvanced only after every object's MERGE has committed

Key design decisions

  • At-least-once reading, idempotent writing. After a crash the batch is simply re-read; the timestamp guard makes the second apply a no-op. Tests replay the whole stream and compare tables, and confirm that batch size doesn't change the result.
  • Partial updates done correctly. Each row records which columns changed, and the MERGE updates only those, so fields an UPDATE event didn't mention keep their values.
  • Loop-safe write-back. Every write-back call is tagged with Sforce-Call-Options: client=.... Salesforce copies the tag into the resulting change events, and the connector drops them.
  • Real Delta Lake in CI without Spark. The local sink uses delta-rs. The Databricks sink shares the same merge plan and generates parameterized MERGE INTO SQL for a Unity Catalog SQL warehouse.
  • Explicit schema evolution. New fields are added with ADD COLUMNS before the merge, so the change is visible in logs.

Run it

git clone https://github.com/gyaneshwarmalba/salesforce-databricks-connector.git
cd salesforce-databricks-connector
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python -m app.main sync      # replays a synthetic 13-event CDC stream into Delta tables
python -m app.main status    # checkpoints, dead letters, table versions
pytest

Status

Working demo with 31 automated tests running in CI. The local Delta path runs end to end; the Databricks SQL sink, Salesforce REST source, and write-back client are tested against fakes but not yet against live orgs or workspaces. A Pub/Sub API (gRPC) subscriber is the natural production source for high volume. It isn't included because it needs a CDC-enabled org to test against.
